# تصميم refactor آمن لقسم المخزون ونقطة البيع

**التاريخ:** 2026-06-28  
**النطاق:** `src/pages/modules/InventoryPosModule.tsx`

## الهدف

إصلاح المخاطر التقنية داخل قسم المخزون ونقطة البيع عبر refactor داخلي محافظ، بدون تغيير السلوك الخارجي للمستخدم، وبدون المساس بقاعدة البيانات أو تسجيل الدخول أو الأدمن الرئيسي أو التدفقات الحساسة التي تعمل بشكل جيد حالياً.

## ما الذي سيتغير

- تقسيم الملف الكبير `InventoryPosModule.tsx` إلى وحدات أصغر وواضحة المسؤولية.
- استخراج الأنواع والثوابت والدوال الخالصة الخاصة بالاستيراد والباركود وPOS والتصدير.
- استخراج أقسام الواجهة الكبيرة إلى مكوّنات فرعية محلية متوافقة مع نفس النصوص ونفس الاستدعاءات.
- تقليل الترابط بين state والمنطق والواجهة داخل نفس الملف.

## ما الذي لن يتغير

- لا تعديل على قاعدة البيانات أو `schema` أو `server/db.ts`.
- لا تعديل على auth أو التسجيل أو الجلسات أو الأدمن الرئيسي.
- لا تغيير على المسارات الحالية أو أسماء API أو شكل البيانات المتبادلة مع السيرفر.
- لا إضافة features جديدة في هذه الجولة إلا إذا كان هناك إصلاح bug واضح يمنع السلوك الصحيح القائم.

## المخاطر الحالية

- الملف `InventoryPosModule.tsx` كبير جداً ويجمع:
  - أنواع وثوابت parsing/import
  - منطق تحميل البيانات وتحديثها
  - منطق POS والباركود وOCR والاستيراد والتصدير
  - واجهة dashboard وPOS والإنتاج والرسائل
- هذا الحجم يرفع احتمال كسر سلوك قائم عند أي تعديل بسيط.
- صعوبة قراءة الملف تجعل إصلاحات المستقبل أبطأ وأكثر عرضة للتعارض.

## المقاربة المعتمدة

المقاربة المعتمدة هي **refactor داخلي محافظ**:

1. الإبقاء على `InventoryPosModule.tsx` كمدخل رئيسي للمسار الحالي.
2. استخراج الوحدات الخالصة أولاً:
   - أنواع وثوابت inventory
   - parsing/import helpers
   - POS draft/barcode helpers
   - export builders
3. استخراج أقسام الواجهة الكبيرة إلى مكوّنات فرعية بدون تغيير props العامة أو السلوك.
4. إبقاء استدعاءات `api(...)` و`fetch...` و`tl...` و`postBackendReportDocx(...)` كما هي، مع تحسين تنظيمها فقط.

## البنية المستهدفة

- `src/features/inventory/types.ts`
- `src/features/inventory/constants.ts`
- `src/features/inventory/import-helpers.ts`
- `src/features/inventory/pos-helpers.ts`

- `src/features/inventory/components/InventoryProductionSection.tsx`
- `src/features/inventory/components/InventoryPosSection.tsx`

قد يتم دمج بعض الملفات إذا ظهر أثناء التنفيذ أن التقسيم الأصغر أكثر أماناً أو أوضح، لكن بدون تجاوز الهدف الأساسي: تقليل الحجم والتشابك.

## التحقق والجودة

- البدء بالدوال الخالصة التي لا تغيّر السلوك.
- المحافظة على نفس مفاتيح الترجمة `t(...)`.
- المحافظة على نفس أسماء الحقول والطلبات ونفس شكل المخرجات في التصدير والاستيراد والرفع والرسائل.
- إجراء تحقق محلي تدريجي بعد كل مرحلة.
- أي bug واضح يظهر أثناء النقل سيتم إصلاحه فقط إذا كان الإصلاح محافظاً ومتوافقاً مع السلوك المتوقع للمنصة.

## معايير القبول

- يبقى القسم قابلاً للتصفح والعمل بنفس الوظائف الحالية.
- لا تتأثر عمليات تسجيل الدخول أو التنقل العام أو الأدمن أو قاعدة البيانات.
- يقل حجم `InventoryPosModule.tsx` بشكل واضح وتصبح مسؤولياته أوضح.
- تصبح الدوال الأساسية قابلة للمراجعة والصيانة بشكل مستقل.
